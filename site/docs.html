Overview

The mayaCharts spec is plain JSON. Rule: x is always the category, y is always the value, whatever the orientation. yDomain is always the value axis.

Customise a chart

Everything below is set in the spec, so it works the same in plain HTML, every framework, server rendering and the builder. Style values can also be set from your own CSS on the maya-chart element, which wins over the spec defaults. Tables are grouped by what you want to change.

Height

A chart takes the height its container gives it. With no definite height (a block in normal flow with height: auto) it keeps a floor so it never collapses to nothing. A definite height, such as a BI tile or a fixed box, wins over that floor, so the chart never spills past its box. Under about 160 px the chart draws a compact frame: no axis titles and fewer ticks. In an element under 200 px tall the title is one line with an ellipsis (the full text shows on hover) and the subtitle is hidden. Older versions kept a 200 px floor everywhere; if a pinned older version overflows a short box, set maya-chart { min-height: 0 }.

The same tokens from CSS

Every theme token is a CSS custom property on the element: the token name in kebab case after --maya-, so fgMuted is --maya-fg-muted and series3 is --maya-series-3. Set them in your stylesheet to style every chart at once. A strict CSP is fine: no inline style attribute is needed. 

maya-chart {
  --maya-font: "Inter", sans-serif;
  --maya-accent: #7c3aed;
  --maya-series-1: #7c3aed;
  --maya-radius: 0px;
}

Not customisable

Line width and opacity per series (dash names the dashed series) and styling of single marks. Charts never take functions in the spec, so formatting is always through format presets, templates and Intl options.

Where the element reads the spec

The <maya-chart> element takes its spec from the first of these that is set: the spec property (assigning data sets it too), then the JSON script child, then the spec attribute. A property you have set wins over any later change to the attribute, so use one source. Assign undefined to the property to fall back to the script child or the attribute.

Embedding in hosts

A host that snapshots a chart (PDF export, scheduled screenshots, a BI tile's render-complete hook) should wait until the chart has settled, not only drawn. maya-render fires after each paint, while entrance and update animations may still run. maya-settled fires after the last animation of that paint, in the same task when nothing animates (animate: false or reduced motion), and also after maya-error with detail.error set. The settled property is a promise for the current or next paint: it resolves when the chart settles and rejects with the MayaSpecError on an error. 

el.spec = spec;
await el.settled; // drawn and still
host.renderComplete();

Drill-through: with drill on, the drill gesture on a mark at the last level fires maya-drill-leaf, whose detail.path holds one raw value per path level, root first. Open the rows behind it, or hand it to your own drill menu. A sankey or chord fires it once drilled to its last branch, where a node's path is known. With select on as well, a click selects for cross-filtering and a double-click or Shift+Enter drills. 

el.addEventListener("maya-drill-leaf", (e) => openRows(e.detail.path)); // ["West", "CA"]

Host adapters do the rest of the plumbing a BI tile repeats. They turn a columnar result into rows, unwrap cells given as { value() } or { value }, match each field written as a RegExp or a case-insensitive name against the returned columns (an unmatched field fails with unknown-field listing the columns), find or create the #chart element, set its spec and return it. They are in mayacharts/host, and in the global builds as maya.host. 

// ThoughtSpot custom chart: reads viz.getDataFromSearchQuery().getData() and calls
// viz.events.emitRenderCompletedEvent() once the chart settles, errors included.
maya.host.thoughtspot(viz, { type: "bar", x: /item/i, y: /sales/i });

// Any host that returns { schema, data: [[...]] }
maya.host.columns({ schema: ["Item", "Sales"], data: [["Shirts", 10]] },
  { type: "bar", x: "item", y: "sales" });

Without a bundler, maya.global.js holds everything. A tile that draws only core types can load maya.core.global.js (the element, the thirteen core types and maya.host) and add one classic script per module type it needs, after the core: maya.hierarchy.global.js, maya.flow.global.js, maya.radial.global.js, maya.geo.global.js, maya.stats.global.js, maya.weave.global.js, maya.units.global.js, maya.orbit.global.js and maya.constellation.global.js. An unknown-type error names the file to add. Each release lists an SRI hash for every global file.

Data fields

An option set to null is treated as unset, as JSON hosts often write it; type and data still need real values.

limit number - Keep top N categories by signed total; rest roll up into "Other" with re-aggregation. A bar with more categories than fit (past 10000 marks) does this on its own when limit is unset, and says so in warnings. bar line area heatmap dumbbell table radial waffle orbit

With series (bar): one ghost per grouped bar. Not with stack

arc 180 / 270 / 360 gauge Sweep of the dial in degrees; 360 is a closed ring. Default 180
forms ("waffle" / "bars" / "swarm")[] units Forms a units chart switches between, first one shown (view.form picks another). With 2 or more the chart shows a form control (text.forms, text.waffle, text.bars, text.swarm). Default all three
form "bars" / "line" radial "line" draws a radar: one closed line per series, angle = x, radius = y from zero; dash draws series dashed, an open line where a series has gaps; hover on a spoke lists every series. Default "bars"

size field scatter beeswarm constellation Bubble, dot or star area (sqrt scale)

stack boolean | "percent" | "stream" | modes[] bar area Stack series instead of grouping. Labels, tooltips and the table show the share, not the raw value. Negative values are shares of the summed magnitudes and stack below 0. horizontal boolean bar dumbbell Categories on the left axis

Time axes

Dates in x values are automatically detected and placed on a proportional time axis when using line, area or vertical bar charts. ISO 8601 dates are recognized as year-month ("2024-03"), full date ("2024-03-05") or date-time ("2024-03-05T14:30:00Z"); a date-time without an offset is read as UTC. A bare year such as "2024" stays a category. Numbers are never auto-detected as dates; use xType: "time" explicitly to interpret them as epoch milliseconds. A time axis preserves the chronological order and spacing of dates, so sort and limit options keep a category axis instead. To disable time axis detection and use a category axis with ISO dates, set xType: "category". All ticks and boundaries are placed at UTC calendar boundaries.

Large data

A chart handles up to a million rows wherever the chart makes sense, by reducing what it draws. Line and area charts reduce long series to about one point per 2 px of plot width (at most 1000 categories, and 4000 shared between series) using the LTTB (Largest Triangle Three Buckets) downsampling algorithm, keeping each series' first, last, minimum and maximum points so trends and extremes remain visible. A time axis reduces whenever it has more points than that budget; a category axis reduces past 1000 categories, over the category index. A kpi thins its sparkline the same way. The data table and screen reader description indicate how many points are displayed. A bar with more categories than fit (past 10000 marks) and no limit keeps the top N by total, N being 10 per 40 px of plot width, and rolls the rest into "Other". Scatter and beeswarm charts above 10000 visible points are drawn as density cells. A table draws the rows that fit its height, and its hidden data table lists the first 1000. The bar roll-up also adds a sentence to renderParts(...).warnings. Charts that cannot reduce without changing meaning (waterfall, dumbbell, parallel and the module charts) fail with too-many-marks, naming the mark count, the 10000 cap and the row count, and suggest limit or aggregate.

The row pass (grouping, aggregation, time parsing, validation) is cached per data array: a resize, legend toggle, zoom or view change re-renders without walking the rows again. The cache is keyed by the array's identity, length, first row and last row, so a push, a shift or a replaced last row is noticed; after editing any other row in place, assign a new array (chart.data = [...rows]).
