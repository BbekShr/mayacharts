## First principles

1. What we learned: prose facts (counts, sizes, test totals) went stale in the same release that changed them, while every spec key stayed in sync. The difference is that keys are checked by `test/schema.test.ts` and prose is not.
2. Foundation: a fact stays true only where one source of truth is checked mechanically. Anything quoted by hand is a copy, and copies drift on the next release.
3. Can it do more: the same check covers README size tables (from `dist/`), the home page stats, the CLAUDE.md test count and the builder's type count. Backlogged as `test/docs-facts.test.ts`.
4. How far: it holds while claims keep a fixed phrasing ("Twenty-seven chart types", "About 56 KB"). Free-form copy cannot be parsed, so the test should pin the few headline phrases and leave the rest to the release checklist.
