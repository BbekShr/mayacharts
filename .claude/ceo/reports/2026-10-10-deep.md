## First principles

1. **What did we learn?** Floating point has a grid: above 2^53 adding 1 does nothing, so any code that widens a range by a constant collapses it and divides by zero. Two encodings of one value must share one clock. A transient clone that carries an id can poison a paint server reference in WebKit for good.
2. **What are the foundations?** IEEE 754 spacing (one ulp is about 1e-16 of the value, so pad by `|v| / 1e15`); perceptual binding (the eye reads an arc and its numeral as one quantity only if they move together); WebKit resolves `url(#id)` by document-order id lookup at style recompute and does not re-resolve when the first match is removed. A bar's length encodes distance from zero, and a gauge is a bar bent into an arc, so its fill starts at zero.
3. **Can it do more?** The ulp rule applies to every degenerate domain (scatter x, beeswarm, gauge nice max). The id rule applies to every ghost or crossfade that clones a group with clipPaths, markers or filters, not just the grid. The one-clock rule applies to bar labels counting beside growing bars and to the kpi bullet beside its headline.
4. **How far can it go?** Doubles overflow past 1e308, hence the 1e300 caps. Count-up still holds and snaps for accounting parentheses or a trailing minus. The gradient ids are fixed per slot, a documented ceiling; per-chart ids would remove the WebKit class of bug entirely at a byte cost.
5. **Industry (speculation).** "The browser is the chart engine" holds, but its engines disagree at the edges (paint server binding, CSS `d` interpolation), so a library built on platform primitives needs per-engine frame tests as a first-class gate, not unit tests. Most libraries still hide this by redrawing everything each frame.
