## First principles

1. What did we learn? A compensating offset is only right in the frame that is actually held. The box glide holds the box top, so any mark offset computed against the plot bottom doubles the move. Two attempts at the bar drill failed on this.
2. Foundations: WAAPI start keyframes compose with the element's layout at t=0; a `translate` on the container and a `transform` on the child add. The check that catches it is the first frame against the frame before the click, which a per-frame "marks match axes" metric cannot see.
3. Can it do more? The same held-frame rule applies to every slot change that moves the box: legend rows, the title, facet scale controls, the kpi back face. One shared rule (reserve the slot, or glide marks and axes in one frame) would retire several backlog items.
4. How far can it go? The always-present empty axis groups make "has axes" undecidable from markup; a mark-level `axes` flag (already in `Mark`) is the reliable signal.
5. Industry (speculation): libraries that tween in data space (D3, ECharts) never meet this because the whole frame re-lays out per tick. A browser-native library that animates the final DOM with transforms must treat layout shifts as part of the transition, which is the cost of letting the browser do the work.
